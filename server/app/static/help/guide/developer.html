开发者工具与 PR ​

给写程序的同事用。IT 在安全中心打开「开发者工具」后，办事模式多出这些能力（这类任务会用后台配置的编程模型）：

工具作用
grep按内容搜代码，支持 ** 通配符
multi_edit一次改一个文件里的多处
git_status / git_diff / git_log查看状态、改动、历史
git_commit提交
create_pull_request推送当前分支并建 PR（每次都要你确认，不能从默认分支建）
pr_status / watch_pull_request查 PR 状态 / 开始盯一个 PR

输入框打 /init，AI 会读一遍项目，生成项目说明 FLYKNIT.md，以后的任务都会先参考它。

git 操作的确认 ​

按子命令和参数定级：查看类直接执行；提交按规则确认；推送、强制推送、删分支、丢弃修改等按高危每次确认。

仓库面板 ​

右侧「文件」标签上方显示当前仓库、分支、未提交改动、领先 / 落后的提交数：

  • 在 GitHub 上打开仓库或分支、复制分支名、新建或切换分支；
  • 有未提交的改动或任务正在进行时不允许切换分支。

聊天里的 PR 链接 ​

回答里出现 GitHub 的 PR 或 Issue 地址时，会显示成带图标的「#编号」。鼠标停在上面会弹出一张卡片，内容包括：

  • 状态：开放、草稿、已合并、已关闭；
  • 仓库和编号、标题、作者；
  • PR 还显示增删行数和改了几个文件，Issue 显示评论数。

卡片内容用你电脑上的 gh 查询。没装 gh、没登录或没有权限时不弹卡片，链接照常可以点开。

盯 PR ​

建好 PR 后可以让它盯着：

  • 每 50 分钟查一次 CI、冲突、评审和评论，有变化弹通知；
  • 打开自动修复时，CI 失败、出现冲突或评审要求修改，会在原对话里自动开一轮修复（每个 PR 最多 5 轮，操作照常确认）；
  • PR 合并或关闭后自动停止，最多盯 14 天。

GitHub 操作用的是你电脑上的 gh 和你自己的 GitHub 登录，令牌不经过公司服务器。

子代理（IT 开启后才有） ​

复杂任务里，AI 可以临时开子代理去翻代码、查资料：几个只读子代理可以同时跑，能改东西的一次一个，每个操作照常确认。
