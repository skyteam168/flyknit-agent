装到员工电脑 ​

打包 ​

在打包用的 Windows 电脑上，进入 client 目录：

powershell
powershell -ExecutionPolicy Bypass -File scripts\publish-client.ps1 -Version 0.3.0

生成 client\dist\FlyknitBuddy-0.3.0.zip，里面有员工端、命令行 flyknit、更新器、运维代理和安装程序。版本号会编进程序，以它为准。

WebView2 运行时 ​

员工端的界面用的是 Microsoft Edge WebView2 运行时。大部分 Win10 / 11 自带并且会自动更新，但长期不联网、关了 Edge 更新的电脑（常见于 LTSC）可能没装或版本太旧，表现是装完一打开就报错。

新版员工端遇到旧运行时会尽量照常打开（只是窗口拖动改由程序处理），实在打不开会提示「WebView2 组件太旧」。要一次性给这类电脑补上：

  1. 从微软官网的 WebView2 页面下载 Evergreen Standalone Installer（x64），放到 client\redist\MicrosoftEdgeWebView2RuntimeInstallerX64.exe；

  2. 打包时加 -WithWebView2Runtime：

    powershell
    powershell -ExecutionPolicy Bypass -File scripts\publish-client.ps1 -Version 0.3.0 -WithWebView2Runtime

安装程序和运维代理在电脑上没装或太旧时，用包里的离线安装包静默装上（会先校验微软签名，不联网下载）；已经够新的电脑不会重复装。装完离线安装包不会留在 Program Files 里。

已经装好的老电脑

运维代理自己目前不会自动升级，靠它补运行时要求代理是这一版以后的。之前装的电脑，用新版安装程序覆盖安装一次即可（对话、记忆、设置都不受影响）。

包会大大约 170 MB，所以只在需要给老电脑补运行时的那个版本里加，之后的版本可以不加。

发布 ​

管理后台「员工端版本」：上传 zip，版本号填同一个。上传后先是「未发布」，确认无误再点「发布」。

安装（推荐：安装程序） ​

  1. 同一页点「下载员工端安装包」，格式选「安装程序 .exe」，可以起个名字（比如「三车间」）；
  2. 把 FlyknitBuddy-Setup-x.y.z.exe 拷到员工电脑双击，输入一次管理员密码。安装程序会：
    • 把员工端装到 C:\Program Files\FlyknitBuddy，建快捷方式，把命令行 flyknit 加入系统 PATH；
    • 装好运维代理（Windows 服务，负责以后的自动升级），用安装包里的凭证注册，不用填注册密钥；
  3. 员工登录：加了域的电脑点「授权登录」，没加域的输入 Windows 账号和开机密码。

批量安装：FlyknitBuddy-Setup-x.y.z.exe /S 静默安装，可以放进组策略启动脚本或 SCCM。

每下载一次安装包生成一张安装凭证，「已下载的安装包」里能看到每个包登录了几台电脑；包外泄了点「停用」，已登录的电脑不受影响。

自动升级 ​

发布新版本后，员工电脑定时检查、后台下载并校验；员工点「重启升级」或关掉程序后自动换好。替换失败会自动回滚到旧版本。

找出不会自动升级的电脑 ​

自动升级靠运维代理。下面两类电脑不会自动升级，在管理后台「设备」里用筛选按钮能一次找出来：

筛选原因处理
代理未安装用了很早的安装包、免安装版，或者代理连不上服务器没注册上用最新的安装程序覆盖安装一次；设备详情里有排查说明
免安装版员工从产品页下的 zip，解压就用，本身就不带代理用安装程序覆盖安装一次，员工的数据在各自的 %APPDATA%\Flyknit，不受影响

不想再有人装免安装版：「员工端版本」页的「产品页下载」里勾选「只提供安装程序」，产品页就只剩安装程序（本页的「下载员工端安装包」不受影响，IT 照样能下 zip）。

设备详情里还能看到这台电脑的安装方式和 WebView2 版本，界面打不开时先看这里。员工端要升级到这一版之后才会上报，老版本显示「—」。

运维代理升级 ​

运维代理（FlyknitAgent）负责员工端的自动升级。代理自己怎么升级分两种情况：

以后的版本：打开「运维代理自动升级」 ​

管理后台「安全中心」→「运维代理自动升级」，默认关。可以先给一个部门或几台电脑打开（部门 / 设备详情里的安全设置），没问题再全厂打开。

打开后，代理替员工端升级完，发现新版本里带的代理比自己新，就在空闲时把自己也换成新版本：

  • 只用代理自己下载并校验过的员工端安装包里的代理，只升不降；
  • 新代理 3 分钟内没连上服务器，会自动换回原版本；同一个版本失败两次就不再尝试（一次可能只是正好断网），设备详情里会显示「自动升级到 x 失败，已换回原版本」；
  • 代理版本每次变化都记一条审计（工具名 agent_version）。

现在已经装好的老代理：用「安装软件」推一次安装程序 ​

老代理里还没有自动升级的功能，要先换一次。不用跑现场：

  1. 「员工端版本」页点「下载员工端安装包」，格式选「安装程序 .exe」；
  2. 「任务中心 → 安装包」上传这个 FlyknitBuddy-Setup-x.y.z.exe，类型选 exe，静默参数填 /S /deferred；
  3. 「设备」里点筛选「代理版本旧」，全选，点「下发任务」选「安装软件」和刚上传的包。

任务会马上显示成功（「已安排安装」），实际安装在代理回报完后开始，1～3 分钟装完：员工端和代理一起换成新版本，命令行 flyknit 也加进 PATH。装完后这台电脑的代理版本会变新，「代理版本旧」里就看不到它了。

一定要带 /deferred

只填 /S 的话，安装程序一停代理，代理会把正在运行的安装程序也一起结束，电脑会停在「代理已停止」的状态，要重启才恢复。

「代理未安装」的电脑（免安装版、代理没装上）没法远程推，只能现场用安装程序装一次。

命令行 flyknit 的 PATH ​

新版代理每次启动、每次替员工端升级完，都会检查员工端目录在不在系统 PATH 里，不在就补上（不受上面开关控制）。新开的命令行窗口生效。

协议与隐私 ​

《用户协议》《隐私政策》有一份按本系统实际数据处理方式写的默认文本，在管理后台「协议与隐私」修改。改完后员工下次登录要同意新版本。建议请法务看一遍再发布。
