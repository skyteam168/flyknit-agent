# 最近更新

升级到最新版后就能用。员工端会自动升级；命令行 `flyknit` 和员工端装在一起，一起升级。

## 2026 年 11 月

### 在命令行里直接对话

新开 cmd / PowerShell / Windows Terminal，进入文件夹输入 `flyknit`，就能像聊天窗口一样一句一句地交代：回答边生成边显示，每一步操作一行，需要确认的操作在命令行里问你（`y` 允许 / `a` 以后自动 / `n` 拒绝），`Ctrl+C` 停下当前这一轮。

`flyknit -c` 接着上次的对话，`flyknit --resume` 挑一个以前的对话接着聊。→ [终端对话](/guide/terminal)

### flyknit -p 不再「半天没反应」

在命令行里直接运行 `flyknit -p` 时，会边做边显示每一步在做什么，最后再输出结果；放在脚本里时输出不变。→ [命令行脚本与 CI](/guide/cli-and-ide)

### IDE 里更快、能找回以前的会话

- 关掉 VS Code 再打开，可以在插件的会话列表里找到以前的会话接着聊（命令行里也能 `/resume` 接着聊）。
- 回答和过程成段显示，不再一个字一个字地刷屏。
- 命令行和 IDE 默认不开深度思考，长任务明显更快；需要时加 `--think`。

→ [在 IDE 里用](/guide/ide)

### 回答里的 PR 链接显示成卡片

开着开发者工具时，回答里的 GitHub PR / Issue 地址显示成带图标的「#123」，鼠标停上去弹出卡片：状态（开放 / 草稿 / 已合并 / 已关闭）、标题、作者、改了多少行。→ [开发者工具与 PR](/guide/developer#聊天里的-pr-链接)

### 更省额度

- 长对话里，之前的内容可以被模型服务的缓存复用，每多聊一句要重新计费的部分少了很多。
- 读过的大文件、长命令输出会更早地精简，不会每一步都整段重发。
- 去掉了后台反复做的会话摘要。

日常使用不用做任何设置。

### 给管理员

- **按部门隔离**：技能、专家、连接器可以设「使用范围」，只给某些部门或某几台电脑用；范围外的电脑看不到、用不了。→ [管理后台一览](/admin/console#按部门隔离)
- **按部门 / 单台电脑设置安全中心**：比如只给研发部打开开发者工具、命令行 / IDE 接入；设备详情里能单独设置某一台。→ [安全中心](/admin/security-center)
- **用量按用途看**：仪表盘新增「按用途」，分开看正常对话和压缩上下文、任务复盘、整理记忆、生成标题这些后台调用各用了多少，以及模型服务的缓存命中率。→ [管理后台一览](/admin/console)
