# 开发者工具与 PR

给写程序的同事用。IT 在安全中心打开「**开发者工具**」后，办事模式多出这些能力（这类任务会用后台配置的编程模型）：

| 工具 | 作用 |
| --- | --- |
| `grep` | 按内容搜代码，支持 `**` 通配符 |
| `multi_edit` | 一次改一个文件里的多处 |
| `git_status` / `git_diff` / `git_log` | 查看状态、改动、历史 |
| `git_commit` | 提交 |
| `create_pull_request` | 推送当前分支并建 PR（每次都要你确认，不能从默认分支建） |
| `pr_status` / `watch_pull_request` | 查 PR 状态 / 开始盯一个 PR |

输入框打 `/init`，AI 会读一遍项目，生成项目说明 `FLYKNIT.md`，以后的任务都会先参考它。

## git 操作的确认

按子命令和参数定级：查看类直接执行；提交按规则确认；**推送、强制推送、删分支、丢弃修改**等按高危每次确认。

## 仓库面板

右侧「文件」标签上方显示当前仓库、分支、未提交改动、领先 / 落后的提交数：

- 在 GitHub 上打开仓库或分支、复制分支名、新建或切换分支；
- 有未提交的改动或任务正在进行时不允许切换分支。

## 聊天里的 PR 链接

回答里出现 GitHub 的 PR 或 Issue 地址时，会显示成带图标的「#编号」。鼠标停在上面会弹出一张卡片，内容包括：

- 状态：开放、草稿、已合并、已关闭；
- 仓库和编号、标题、作者；
- PR 还显示增删行数和改了几个文件，Issue 显示评论数。

卡片内容用你电脑上的 `gh` 查询。没装 `gh`、没登录或没有权限时不弹卡片，链接照常可以点开。

## 盯 PR

建好 PR 后可以让它盯着：

- 每 50 分钟查一次 CI、冲突、评审和评论，有变化弹通知；
- 打开自动修复时，CI 失败、出现冲突或评审要求修改，会在原对话里自动开一轮修复（每个 PR 最多 5 轮，操作照常确认）；
- PR 合并或关闭后自动停止，最多盯 14 天。

GitHub 操作用的是你电脑上的 `gh` 和你自己的 GitHub 登录，令牌不经过公司服务器。

## 子代理（IT 开启后才有）

复杂任务里，AI 可以临时开子代理去翻代码、查资料：几个只读子代理可以同时跑，能改东西的一次一个，每个操作照常确认。

每个子代理有自己的上下文：它翻过的文件、跑过的命令不会塞满主对话，主 AI 只拿到它交回的结论，所以适合「同时摸清三个模块」这类大任务。编码模式的任务看板上能看到每个子代理在做什么。

### 给子代理换模型

IT 在后台启用了多个模型时，AI 可以给每个子代理选不同的模型：简单的查找、整理用便宜快的，难的推理用强的。能选的就是你在输入框里能选的那些（还要能调用工具）。也可以直接跟 AI 说「用某某模型开子代理去查」。

### 项目里定义好的子代理

把常用的分工写成文件放进项目，AI 可以按名字派，不用每次都交代一遍。文件放在工作区根目录的 `.flyknit/agents/` 下，一个子代理一个 `.md` 文件：

```markdown
---
name: reviewer
description: 改完代码后做代码审查，找 bug 和不符合约定的地方
model: 强模型          # 可选：后台启用的模型名，不填用主 AI 的模型
read_only: true        # 可选，默认 true（只能看，不能改）
tools: read_file, list_dir, grep   # 可选：只给这些工具
---
你是代码审查员：只找 bug 和不符合项目约定的地方，按严重程度排好，写清文件:行号。
```

- 写好后跟 AI 说「改完让 reviewer 审查一下」就行；每次发消息时重新读取，改了马上生效。
- 这些文件只能**收窄**子代理能做的事：工具只能从 AI 本来就有的里面挑，`read_only: false` 时每个改动照样要你确认。
- 写着「忽略之前的规则」这类像在给 AI 下指令的文件不会被采用；最多读 20 个文件，每个不超过 8000 字。
- 文件跟着项目走，可以提交到代码库，整个开发组共用。
