# 无人值守任务

员工电脑上的定时任务要电脑开着才会跑。**无人值守任务**由服务端按时间表派到一台常开的**执行机**上执行，员工下班关机也照常跑；做完的结果作为「**定时报告**」发到指定部门或电脑的消息中心。

适合：每天早上的产量日报、每周一的生产周报、每小时检查一次异常停机……凡是「到点拉数据、出报告」的事。

## 准备一台执行机

1. 找一台不给员工用的电脑或虚拟机（Windows 10/11），装 FlyknitBuddy，用专门的账号登录；
2. Windows 设成**自动登录**、**开机自动启动 FlyknitBuddy**，电源计划设成「从不睡眠」；
3. 把这台电脑要用的连接器（如中台）、技能装好、登录好；
4. 在「设备列表」里给它写个备注（如「无人值守执行机」），需要的话单独给它设安全设置。

## 建任务

后台「**运维 → 无人值守任务**」：

| 项 | 说明 |
| --- | --- |
| 交给 AI 的要求 | 像平时跟 FlyknitBuddy 说话一样写，比如「用中台查上周各车间的产量、达成率和不良率，和前一周对比，用表格列出，最后写三条需要关注的地方」 |
| 时间 | 每天 / 工作日 / 每周几 / 每月几号 / 从某个时间起每隔几小时；时区选越南或中国 |
| 执行机 | 选上面准备好的那台 |
| 结果发给 | 部门、个别电脑；**都不选就不发**，只在这页的执行记录里看 |
| 权限上限 | 仅可查看 / 工作区内修改（没有完全权限） |
| 只预演 | 新建默认打开：只列出会做什么、不真的改。看过几次结果没问题再关掉 |

页面右上角的**总开关**默认关闭，只有超级管理员能打开。关着时到点不派发；打开后不会把关着期间错过的一次补跑一堆。

## 规则

- 执行机前没有人：需要员工确认的操作一律不做，被拒的会写在结果里；
- 上一次还没做完，这一次自动跳过；
- 建任务、改任务、立即运行需要「能下发指令」的管理员账号；
- 做失败的报告会标为重要，写明原因（比如连接器没连上）。
