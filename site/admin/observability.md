# 可观测性（OpenTelemetry）

公司如果已经有可观测平台（OpenTelemetry Collector、Grafana、Jaeger、SigNoz、云厂商的 APM 等），可以把 FlyknitBuddy 的调用数据也接进去：某个任务为什么慢、哪个模型最近错误多、哪个连接器的工具经常失败，都能和其他系统放在一起看。

## 会发什么

| 数据 | 内容 |
| --- | --- |
| 每一次模型调用 | 模型、场景、输入 / 输出 token、耗时、是否出错 |
| 每一次工具调用 | 工具名、风险判定、谁批准的、成功与否、是主助手还是专家调的 |

同一个任务的调用在同一条追踪（trace）里，点开就能看到这个任务先后调了几次模型、用了哪些工具、每一步多久。

**不会发**：对话内容、工具的参数和结果、文件路径。默认也不带电脑名和使用者，只带电脑编号和部门。

## 怎么打开

后台「**运维 → 可观测性**」（超级管理员才能修改）：

1. 填**采集器地址**，例如 OpenTelemetry Collector 的 OTLP/HTTP 端口；会自动加上 `/v1/traces`；
2. 采集器要认证的，加一个**请求头**（比如 `Authorization`），值保存后加密，页面上不再显示；
3. 点「**发一条测试数据**」，确认采集器收到了；
4. 打开「**导出**」开关并保存。

页面下方能看到已发出、排队中、丢弃的条数和最近一次出错的原因。采集器出问题时只会丢掉那一批数据，不会影响员工使用。

::: tip 带上电脑和使用者
需要按人排查时，可以打开「带上电脑和使用者」。这些数据会进入公司的可观测平台，请先确认符合公司的隐私规定。
:::
