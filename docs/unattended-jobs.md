# 无人值守任务

状态：第一期已实现，总开关默认关闭。2026-11。

## 1. 为什么

员工电脑上的「定时任务」要电脑开着、FlyknitBuddy 开着才会跑；下班关机，第二天早上 8 点的报表就没了。
中台接入后的「到点自动拉数、出报告」，不能依赖某个员工的电脑。

## 2. 做法

**执行机** = 一台常开的专用电脑或虚拟机，装普通的 FlyknitBuddy 桌面版、设好自动登录和开机启动。
不另做一套无界面执行器：桌面版本来就会领取服务端派来的任务（事件触发、钉钉、手机都走这条路），
连接器、技能、浏览器、电脑操作都能用（命令行版没有这些；电脑操作本来也需要一个登录着的桌面）。

服务端负责按时间表派发、结果送达：

```
后台「无人值守任务」 ─┐
                      │ 到点（每 30 秒检查一次）
                      ▼
          通道消息 channel=unattended ──► 执行机上的 FlyknitBuddy 领走执行
                      ▲                        │ 没人在场：需要确认的一律拒绝
                      │ 回报结果                 │ 权限按任务的上限封顶（服务端核对授权）
                      └────────────────────────┘
                      │
                      ▼
          「定时报告」通知 → 指定部门 / 电脑的消息中心
```

| 层 | 位置 | 做什么 |
| --- | --- | --- |
| 服务端 | `app/models.py` `UnattendedJob` | 任务：要求、执行机、权限上限、只预演、时间表、UTC 偏移、收件人 |
| 服务端 | `app/services/unattended_service.py` | 时间表计算、到点派发（`tick`，每 30 秒）、结果送达（`deliver`）、Markdown → HTML |
| 服务端 | `app/routers/unattended.py` | 后台接口：列表、建 / 改 / 删、立即运行、总开关 |
| 服务端 | `channel_hub.finish`、`grants.py` | 回报时送达；授权来源 `unattended` 按派发记录核对电脑和权限上限 |
| 员工端 | `AgentHost.Channels` / `Grants` / `Router`、`TaskGrant`、`TaskOrigins` | 认 `unattended` 来源：无人在场、服务端核对、不归档成追问 |
| 员工端界面 | `features/notices/meta.ts`、i18n | 通知类型「定时报告」（report）、任务来源「无人值守任务」，三语 |
| 后台 | `admin/src/views/Unattended.vue` | 「运维 → 无人值守任务」页面 |

## 3. 规则

1. **总开关**（设置表 `unattended.enabled`）默认关，只有超级管理员能开。关着时到点不派发，时间自动顺延，打开后不会一下子补跑一堆。
2. **谁能建任务**：具名且「能下发指令」的管理员（和指令中心一样）；共享的管理令牌不行。
3. **权限上限**只能是「仅可查看」或「工作区内修改」，没有「完全权限」；新建默认「只预演」。
4. **没人在场**：需要员工确认的操作一律拒绝（和钉钉、事件触发同一套 `RemoteDecline`），被拒的写进结果里。
5. **不堆积**：上一次还在排队或执行中，这一次跳过（后台提示「跳过了」）；服务端停机期间错过的多次只补一次。
6. **结果送达**：收件人是部门 ∪ 电脑；**两个都空就不发**（消息中心里空范围等于全公司，这里刻意不发）。做成了发正文（Markdown 转成 HTML 再按白名单清洗）；失败的发原因并标为重要。
7. **时间表**：每天 / 工作日 / 每周几 / 每月 1–28 号 / 从某个时间起每隔 N 小时（到第二天的那个时间重新对齐）；时区用固定 UTC 偏移（越南、中国没有夏令时）。

## 4. 执行机怎么准备

1. 一台不给员工用的电脑或虚拟机（Windows 10/11），装 FlyknitBuddy，用专门的账号登录，在后台设备列表里写清楚备注（如「无人值守执行机」）；
2. Windows 设成**自动登录**、**开机自动启动 FlyknitBuddy**；电源计划设成「从不睡眠」（任务执行期间程序自己也会阻止睡眠）；
3. 这台电脑需要的连接器（如中台）、技能装好、登录好；
4. 按需要给这台电脑单独的安全设置（设备列表 → 安全设置），比如只给它开电脑操作。

## 5. 验收

- 服务端：`tests/test_unattended.py`（时间表、Markdown、权限、派发与跳过、授权核对、送达范围、失败报告）。
- 真机：一台执行机 + 一个每 1 小时的只预演任务；关掉自己的电脑，看第二天消息中心里有没有报告、后台执行记录是否完整。

## 6. 以后

- 员工在自己的定时任务里一键「交给执行机跑」（现在只有 IT 在后台建）；
- 报告带附件（Excel）：执行机上传产出文件，通知里给下载链接；
- 结果同时推企业微信群。
