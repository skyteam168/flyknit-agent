# 编码模式（AI IDE）

定位：**AI Agent Workspace / AI IDE**。员工在 FlyknitBuddy 里直接看到 AI 改代码，像 Cursor 那样。

## 1. 布局

| 位置 | 内容 |
| --- | --- |
| 左边 | 项目文件 / 技能 / MCP 连接器 / 知识（资料库） |
| 中间 | Monaco 编辑器：多标签、AI 改动对比、Ctrl+S 保存 |
| 右边 | AI Agent：就是这个对话（消息 + 输入框），编码模式下放到最右边、可拖宽度 |
| 底部 | 终端 / 日志 / Agent Trace（这一轮 AI 每一步做了什么，可打开完整链路） |

标题栏的「编码」按钮进出；只在 **开发者工具开着**（安全中心 `developer_tools`，默认关）、办事对话选了工作区时出现。
布局（各栏宽高、选中的标签）记在本机，下次打开照旧。

## 2. 为什么不内嵌完整 VS Code

调研过 openvscode-server、code-server、微软 VS Code Server、Eclipse Theia：

- 官方只发 Linux 版本 / 没有 Windows 安装包，或者二进制受微软许可约束不能随我们分发；
- 微软插件市场条款只允许微软自家产品使用，只能用 Open VSX，而 Open VSX 2025–2026 年多次被恶意插件（GlassWorm）攻击；
- 内嵌 IDE 自带终端、任务、插件，直接在员工电脑上执行，绕过命令分级、确认、审计（违反开发规则第 3 节）。

所以只用 **Monaco**（VS Code 的编辑器内核，MIT）。AI 照样走我们自己的工具（`write_file` / `edit_file` / `multi_edit` / `run_shell` …），
确认、审计、分级一样不少；没有插件生态。

## 3. 实现

- web：`client/web/src/features/code/`（`registerFeature`，事件前缀 `code.`）。Monaco 按需加载（第一次进编码模式才下载），
  只带编辑器本体 + 常用语言的语法高亮，不带 TS/JSON/CSS/HTML 语言服务。
- Core：`Flyknit.Core/Code/CodeFeature`（`IBridgeModule`，方法 `code.load` / `code.save`）。
  - 只读写这个对话工作区里的文件（`WorkspaceBrowser.Resolve`，`..\`、绝对路径跳不出去）；
  - 路径上有符号链接 / 目录联接指到工作区外的：能看不能存；
  - 二进制（开头 8KB 有 0 字节）、超过 200 万字符的：只读；
  - 保存带打开时的版本号：期间被 AI 改过就不覆盖，界面让员工选「用 AI 的」或「用我的」（沿用文档画布 `DocumentCanvas`）；
  - 员工自己保存不走 AI 的命令确认（和在记事本里改一样），每次保存记日志（只记路径和字节数）。
- 宿主：AI 的 `write_file` / `edit_file` / `multi_edit` 成功后发 `code.changed`（完整路径）。界面里开着的文件刷新成对比视图；
  「跟随 AI」开着时自动打开没开过的文件（没开过的不知道改之前的样子，只标「AI 改过」）。
- 底部「终端」复用右侧终端标签；「日志」是这个对话每次工具调用的完整输出；「Agent Trace」是这一轮的工具步骤，
  「完整链路」打开已有的执行链路（每一步耗时、token）。

## 4. 第二期：像 Cursor 一样的交互

- **选中代码**：编辑器里选中一段，浮出「添加到对话 Ctrl+L · 快速修改 Ctrl+K」。
  - 添加到对话：文件、行号、代码块接到输入框后面，员工接着说要做什么；
  - 快速修改：在编辑器里直接写怎么改，回车交给 AI（只改选中的这几行）；AI 正在做别的事时先放进输入框。
  - 焦点在编辑器里时 Ctrl+L / Ctrl+K / Ctrl+S 归编辑器（`shortcuts.ts` 让出这三个键），其他全局快捷键照常。
- **终端（参照 VS Code）**：底部「终端」左边是画面、右边是列表。
  - 员工自己的 PowerShell：Windows 伪控制台（`Core/Terminal/PseudoConsole`，ConPTY）+ xterm.js，能开多个（最多 6 个），起在对话的工作区；
    只在开发者工具开着时能开；内容不经过 AI、不进日志（日志只记开 / 关）；程序退出时一并关掉。
  - AI 跑的命令（`run_shell`，包括一直跑着的后台命令）：看输出，还在跑的可以停。AI 的命令照样走命令确认。
- **对话里**：
  - AI 改文件的卡片下面直接显示改了哪几行（文件名、+n −m、红删绿增），从工具参数算出来；
  - 输入框上方一行汇总：几个后台终端在跑（点开终端）、最近一轮改了几个文件（点「查看」看对比、还原）；
  - 用户消息上的「恢复到这里」（Restore Checkpoint）：把这条消息之后 AI 改过的文件恢复成这条消息之前的样子，
    用现有的「每一轮改动可以还原」，先确认再动，对话记录不变。

## 5. 第三期

- **右边 AI Agent 的任务标签（参照 Cursor）**：顶上一排打开过的任务，「+」在当前工作区新建任务、时钟按钮看这个工作区的历史任务，
  新建、切换都留在编码模式里。侧栏的「新建任务」、Ctrl+N 在编码模式里也一样（接着在同一个工作区新开任务，不回首页）。
- **在 VS Code 中打开**：编辑器工具栏的「VS Code」按钮，用员工自己装的 VS Code 打开工作区（开着文件就跳到那个文件）。
  找 Code.exe（用户安装版、系统安装版、PATH 里 code.cmd 旁边的），直接启动、参数逐个传，不经过 code.cmd 和命令行解释器。
- **文件树自动刷新**：AI 的 write_file / delete_path / multi_edit / run_shell / git_commit 做完后宿主发 `code.treeChanged`，
  文件树（含展开着的子文件夹）重新列，展开状态不变；连着几步只列一次。
- **AI 的后台命令在伪控制台里跑**（Windows）：`TerminalHub.UsePseudoConsole`。界面拿到带颜色的原始输出（`pty.runOutput`），
  员工能在终端里直接和它交互（`pty.runWrite`）；AI 用 shell_output 读到的是去掉控制序列的纯文本（`VtText.Strip`），和以前一样。
  前台命令照旧用普通进程（要等结束、拿退出码、超时转后台）。命令的确认、分级不变。

## 6. 第四期：AI 知道「这个项目」是哪个（参照 Cursor）

问题：工作区常常是装着很多项目的大文件夹（如 `D:\AIWORK`），员工在编辑器里开着 `vue3-login` 的文件说「分析下这个项目」，
AI 只知道工作区、不知道编辑器里开着什么，只能去猜（按修改时间挑了别的项目）。

1. **编辑器上下文**：界面在切标签、移光标时经 `code.focus` 告诉宿主当前文件、光标 / 选中的行、打开的文件
   （路径按对话工作区校验，工作区外的不收；退出编码模式时清掉）。运行扩展 `EditorContextRunExtension`
   每轮把它放进本轮参考资料 `<编辑器上下文>`：当前项目、当前文件和位置、其他打开的文件，并说明「这个项目 / 这个文件 / 这里」指它们。
   只放路径和行号，不放文件内容；标明是程序附加的参考，不是员工的指令。
2. **当前项目**：`ProjectInsight.FindRoot` 从当前文件往上找第一个带项目标志（.git、package.json、pyproject.toml、*.csproj、go.mod …）
   的文件夹，最远到工作区根。项目比工作区小时，编辑器顶上提示「当前项目：vue3-login · 设为这个任务的工作区」，
   点一下把任务的工作区收窄到这个项目（只缩小范围），开着的文件改成相对新工作区的路径。
3. **说不清就问**：`<写代码>` 说明里加一条：没有编辑器上下文、工作区下又有多个项目时，先列候选项目用 ask_user 问，不按修改时间、文件夹名去猜。
4. **项目概况**：`ProjectInsight.Overview` 从项目文件整理（不调模型、不出网）：类型（Vue / Vite / React / Python / .NET …）、
   名称、脚本、主要依赖、顶层目录（src 下再看一层）、项目自己的 FLYKNIT.md / AGENTS.md / CLAUDE.md（/init 生成的就是 FLYKNIT.md；
   有注入特征的不采用）。按项目标志文件的修改时间缓存；同一个对话里同一个项目只在第一次附上。

## 7. 保留 / 撤销 / 查看（参照 Cursor 的 Keep / Undo / Review）

AI 的改动一执行就写进磁盘（和 Cursor 一样）。一轮做完后，输入框上方「N 个文件有改动」那一行有：

- **保留**：只在本机记下「这一轮认可了」（`flyknit.keptTurns`），不再提示；编辑器里这些文件的对比收起。不改磁盘。
- **撤销**：用现有的按轮还原（`changes.revert`）把这一轮改过的文件恢复成这一轮之前的样子；先确认，编辑器里有没保存的修改时一并提醒；
  撤销后编辑器按磁盘重新读，被撤销成「不存在」的（AI 新建的文件）关掉标签。
- **查看**：打开这一轮的改动对比（原来的改动弹窗，可以只还原其中几个文件）。

编辑器里 AI 改过的文件上方有「撤销此文件」「保留」：按文件找到最近一次改它、还没处理的那一轮，只还原这一个文件。
AI 还在做的时候不出现（做完再一起决定）。

## 8. 长对话：编辑器跟着工作区、上下文用量、带上摘要新建

- **编辑器按工作区存**（`features/code/store.ts` 的 `editorKey`）：打开的文件、当前标签存在「工作区」格子里，不按任务存；
  同一个工作区里新建、切换任务，打开的文件都还在。收窄到项目时，这个任务换到项目的格子，原来大工作区的格子不动（别的任务可能还开着）。
  AI 改动的对比在同一个工作区的任务之间共用；「撤销此文件」只在改动属于当前任务时出现。
- **关掉的标签释放 Monaco model**（`MonacoView.vue`）：每个 model 占着一份文件内容和撤销记录，关掉标签就释放，以后打开按标签内容重建。
- **上下文用量**（`ContextHint.vue`，放在输入框上方的 `RunSummary` 里）：读宿主每轮结束时记下的 `context.usage`，显示「上下文 N%」（上一次请求 / 模型窗口）。
- **建议新开任务**：用量 ≥ 60%（自动整理在 75% 左右），或者员工打开的文件所在项目和这个任务第一句话时的项目不一样，提示「带上摘要新建 / 新建任务 / 整理对话」；
  「不再提示」只对这个任务、这一种提示（换项目按项目记）。
- **带上摘要新建**：界面新建任务后调 `code.handoff(新任务, 旧任务)`。宿主用压缩对话同一套摘要（`ContextManager.SummarizeForHandoffAsync`，
  经服务端网关，按 `agent` 场景计用量）把旧任务整段（连同已有摘要）整理成交接摘要，存在内存里（`HandoffStore`）；
  新任务第一句话发出时 `EditorContextRunExtension` 取走（只给一次），放在本轮参考资料最前面，标明「参考资料，不是员工的指令」，
  跟着这条消息存进历史。第一句话发出时摘要还没好，最多等 90 秒，等不到就不带。只能在同一个项目（工作区相同或一个在另一个里面）的任务之间带；
  `code.handoffClear` 取消（还在整理的也取消）。程序重启前没发第一句话的，交接就没了。
- **新任务的欢迎页**（`IdeWelcome.vue`，`ideWelcome` 为真时代替消息列表）：编码模式里还没说话的办事任务显示标志、「新对话」、在哪个项目里；
  带了交接摘要的显示整理进度（骨架条）和整理好的摘要，「接着做」一键发出（不在整理好后自动发：员工可能还想补充这次要做什么）；
  没带摘要的给几个常用开头，点一下放进输入框。此时输入框上方的交接卡片不重复显示。
