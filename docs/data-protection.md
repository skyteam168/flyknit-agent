# 数据保护：发给外部模型前脱敏

状态：已实现第一期（2026-11）。代码：`server/app/services/dlp.py`、`server/app/routers/gateway.py`、`server/app/routers/dlp.py`。

## 1. 为什么在服务端网关做

员工电脑上所有模型调用（对话、办事、专家、子代理、团队、翻译、压缩、标题、记忆向量）都必须经过
`/api/v1/chat/completions` 和 `/api/v1/embeddings`，员工端绕不过去，模型 Key 也只在服务端。
这是唯一的出网口，符合「关键安全约束在服务端执行」。

## 2. 怎么做：可还原的假名化

1. **识别**（`dlp.mask_text`），只认有固定格式、能校验的：
   - 身份证：18 位、出生日期合法、校验码正确；
   - 银行卡：16～19 位（允许空格、横线分组）、Luhn 校验通过、且不是身份证；
   - 手机号（中国大陆 11 位，可带 +86）、邮箱：受「手机号、邮箱也换」控制；
   - 密码 / 口令 / 密钥 / 令牌 / 私钥：只认值（`password=xxx`、`sk-…`、`Bearer …`），换成 `〔已隐藏〕`，**不还原**。
2. **替换**：同一次请求里按出现顺序编号，同一个值同一个占位符（`[身份证_1]`）。
   请求之间不存对照表：员工端每次发的是带原值的完整历史，前缀不变时编号也不变，提示词缓存照样命中。
   有替换时在第一条系统消息后面加一段说明，告诉模型原样使用占位符。
3. **还原**：
   - 非流式：`restore_payload`（正文、思考、工具调用参数；参数是 JSON 文本，原值按 JSON 转义）；
   - 流式：`StreamRestorer` 按 SSE 事件解析，每个字段各自缓冲，占位符被拆在两段里也能拼回来；回答结束时把压着的半截放出去。
   - 没有替换时一个字节都不动，原样转发。
4. **拦截档**（`dlp_block`）：发现身份证、银行卡、手机号、邮箱就返回 400 `sensitive_data_blocked`，不发；
   只有密码密钥时照常隐藏后发出。
5. **记录**：`dlp_events` 只记电脑、场景、处理方式、各类型数量，不记原值和对照表。

联网搜索的搜索词用脱敏后的那份。公司自己服务器上的聊天归档照旧是原文（数据没有出公司）。

## 3. 开关（安全中心，全厂 → 部门 → 单台电脑）

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `dlp_enabled` | 关（锁定） | 总开关 |
| `dlp_contacts` | 开 | 手机号、邮箱也换 |
| `dlp_block` | 关 | 发现就拦下不发 |

## 4. 管理后台

「数据保护」页：最近 N 天换了 / 拦了多少（按类型、按电脑）、最近记录、「试一试」（贴一段文字看会换成什么，不发给模型、不记录）。

## 5. 管不到的（后续）

- 图片、语音里的号码：敏感部门可以关掉带图 / 语音，或者走内网模型；
- 姓名、住址、工资金额等自由文本：规则抓不全。真正不出公司的做法是给这些部门配内网部署的模型（后台已支持多个模型服务商，按场景 / 部门路由）；
- IT 自定义规则（工号、客户编号格式）。
