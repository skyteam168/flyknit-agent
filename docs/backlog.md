## D. WebView2 运行时太旧 / 没装

**现象**：部分电脑装完一打开就报错（截图里是 `ICoreWebView2Settings9` 相关的「登录界面加载失败」），单独装一遍 WebView2 Runtime 才好。

**原因**：
- 登录窗口（`LoginWindow.cs`）和主窗口（`MainWindow.xaml.cs`）都设置了 `Settings.IsNonClientRegionSupportEnabled = true`，
  这个属性在 `ICoreWebView2Settings9` 上，**电脑上的 WebView2 运行时太旧就没有这个接口**，一设置就抛异常，整个界面起不来。
- 运行时太旧 / 没装常见于：长期不联网、关了 Edge 更新的 Win10 LTSC、新装系统还没来得及更新的电脑。
- 现在只认 `WebView2RuntimeNotFoundException`（完全没装）；装了但版本旧的情况落到通用异常，提示看不懂。

**做法（三层，越往后越治本）**：

1. **降级运行（不再因为旧运行时打不开）**
   - 两处 `IsNonClientRegionSupportEnabled` 包一层：设置失败就记日志、标记「不支持页面拖动区域」，继续启动。
   - 拖动窗口改走桥接兜底：宿主把这个能力告诉页面；不支持时页面在 `app-region: drag` 的区域上按下鼠标就发 `window.drag`，
     宿主用 `ReleaseCapture` + `WM_NCLBUTTONDOWN(HTCAPTION)` 拖动（和系统标题栏同样的行为，双击照样最大化 / 还原）。
   - 其他用到新接口的地方（如有）同样检查一遍，统一放进一个 `WebViewCompat` 工具类。
2. **启动时检查版本，给看得懂的提示**
   - `CoreWebView2Environment.GetAvailableBrowserVersionString()` 拿到版本：没装 → 现在的提示；低于最低版本 → 新提示
     「这台电脑的 WebView2 组件太旧（当前 x.x，需要 y.y 以上），请让 IT 更新，或运行安装包重新安装」，三语（`NativeStrings`）。
   - 降级后能用的照常进入，只是在日志和设备上报里标出运行时版本，后台设备详情能看到「WebView2 版本」，IT 好排查。
3. **安装时顺带装好运行时（治本）**
   - 打包时可选放入微软的离线安装包：`client\redist\MicrosoftEdgeWebView2RuntimeInstallerX64.exe`（Evergreen Standalone，约 170 MB；
     不放就跟现在一样，安装包体积不变）。
   - `Setup.exe` 安装前检查运行时：没装或低于最低版本，且包里有离线安装包时，静默安装（`/silent /install`），失败不阻断安装、只提示。
   - 运维代理升级时同样检查（SYSTEM 身份，可以静默装），让已经装好的老电脑也能补上。
   - 离线安装包从微软官网下载后由 IT 放进发布包，**不从员工电脑联网下载**（工厂电脑很多不通外网）。
4. **操作系统检查**
   - `Setup.exe` 启动先检查系统版本：低于 Win10 1809（.NET 8 的下限）直接提示「不支持 Windows 7 / 8，请升级到 Windows 10 或 11」，不往下装。
   - 员工端启动同样检查一次，给同样的提示（防止有人拷贝免安装版到 Win7 上）。

**安全**：离线安装包只从发布包里取，校验微软签名（`WinVerifyTrust`）后才运行；不接受服务端或员工给的路径 / 网址。

**测试**：
- Core / Client 可测部分：版本比较（`CompareBrowserVersions` 包装）、系统版本判断、提示文案三语齐全。
- `Setup` 单测：包里有 / 没有离线安装包、已装新版不重复装、签名校验失败不运行。
- 实机：一台卸载 / 降级了 WebView2 Runtime 的 Win10 虚拟机，验证三种情况（没装、旧版、新版）。

**验收**：在出过问题的那类电脑上，不单独装 WebView2 也能打开 FlyknitBuddy、窗口能拖动；带离线安装包的发布包装完后运行时版本达标。

## E. 安装问题：免安装版、没装上运维代理

**现象**：后台「设备」里一部分电脑的运维代理显示「未安装」，这些电脑**不会自动升级**。

**原因**（11-12 排查）：
- 员工从产品页下的是 **zip 免安装版**，解压就用，没有运维代理（只有 `Setup.exe` 会装代理）。
- 用的是很早以前的安装包（那时还没有代理）。
- 装了代理但服务器地址填错 / 连不上，没注册上。

**做法**：
1. **后台可以只提供安装程序**：系统设置加「产品页只提供安装程序（隐藏 zip）」，**默认关**（保持现状）；
   打开后 `/public/release` 的 `formats` 不含 zip、`/public/download?format=zip` 返回 404。IT 自己的发布管理里照样能下 zip。
2. **员工端上报安装方式**：心跳 / 设备信息里带 `install_kind`：`setup`（在 Program Files、注册了卸载项）或 `portable`（其他）。
   服务端字段**只加不删、有默认值**（`unknown`），老版本不报也不出错。
3. **后台设备列表标出来**：代理列旁边标「免安装版」；设备详情里写清楚怎么补装（下载安装程序覆盖安装即可，会话、记忆、设置都在 `%APPDATA%\Flyknit`，不会丢）。
   支持按「免安装版 / 代理未安装」筛选，方便 IT 一次找出来。
4. **员工端提示一次**：免安装版且没有运维代理时，在设置 →「关于」里显示「当前是免安装版，不能自动升级」，带下载安装程序的按钮（三语）。
   只在「关于」里显示，不弹窗打扰。

**安全**：`install_kind` 只是展示用，不影响任何权限或策略；隐藏 zip 是展示层开关，不涉及鉴权。

**测试**：服务端 `test_landing`（开关开 / 关时的 formats 和下载结果）、设备上报新字段（有 / 没有都能存）；web 构建（三语）；admin 构建。

**验收**：打开开关后产品页只剩「下载安装程序」；用 zip 启动的电脑在后台显示「免安装版」，按说明覆盖安装后变成「代理在线」。

## F. 视频预览

**现象**：AI 生成或找到的视频（mp4 等）在聊天产出卡片、文件预览里显示成「文件信息」，不能播放；只有资料库查看器（`LibraryViewer.vue`）能放。

**原因**：预览系统（`Flyknit.Core/Preview/Providers.cs`）没有视频类型；图片走 dataUrl，视频动辄几十上百 MB，不能这样塞进消息。

**做法**：
- **新增预览类型 `video`（顺带 `audio`）**：mp4 / m4v / webm / ogv / mov（H.264）；mp3 / wav / m4a / ogg。
  WebView2 放不了的（avi / wmv / mkv / flv）照旧显示文件信息，加「用系统播放器打开」按钮。
- **流式读取，不进消息**：仿照资料库的 `files.flyknit.local`，新增虚拟地址 `https://media.flyknit.local/{令牌}`：
  - 宿主在预览时给这个文件发一个**随机令牌**（只在本次运行内有效、和文件路径一一对应），页面只拿到令牌地址，拿不到任意路径；
  - 文件本身照常过预览的访问检查（和现在点开预览一样的工作区 / 产出文件判断）；
  - `WebResourceRequested` 里按 `Range` 头返回 `206 Partial Content`，可以拖进度条；不带 Range 时返回整个流。
- **前端**：`PreviewPane.vue` 加 `video` / `audio` 分支（`<video controls>`、`<audio controls>`），产出卡片上的视频显示首帧缩略和时长。
- 只做本机文件；网页里的视频不管（浏览器工具本来就能放）。

**安全**：令牌随机、不可猜、不落盘；只映射已经通过预览检查的文件；只读，不能写；`Range` 解析在 Core 里做、带上下界检查。

**测试**：Core 补 `Range` 解析（正常、越界、多段只取第一段、非法格式）、令牌表（未知令牌 404、过期 / 释放后不可用）、预览类型判断（视频 / 音频 / 不支持的格式）；web 构建（三语）。

**验收**：让 AI 生成一个 mp4（或打开工作区里已有的视频），产出卡片和预览面板里能直接播放、拖动进度条；200 MB 的视频打开不卡界面。

## A. 旧电脑升级后补 PATH

**问题**：命令行功能加入前装的电脑，自动升级会把 `flyknit.exe` 放进 `C:\Program Files\FlyknitBuddy`，
但把这个目录加进系统 PATH 只有安装程序（Setup.exe）做，运维代理升级时不做。结果老电脑升级后敲 `flyknit` 提示「不是内部或外部命令」。

**做法**：
- 运维代理（`Flyknit.Agent/ClientUpdater.cs`，SYSTEM 身份）整目录替换成功后，检查系统 PATH 里有没有员工端目录，没有就补上；
  复用安装程序的 `Flyknit.Setup/PathList.cs`（只加这一个目录，不动别的项，去重、大小写不敏感）。
- 只在员工端目录里确实有 `flyknit.exe` 时补。
- 补完广播 `WM_SETTINGCHANGE`，新开的命令行窗口立即生效（已开的窗口不会变，这是 Windows 的规矩）。
- 卸载时照旧由安装程序去掉。

**安全**：只写 HKLM 的 Path 值里这一项；目录是代理自己管的 Program Files 路径，员工改不了；不接受来自服务端或员工的路径。

**注意（11-12 发现）**：运维代理**自己不会升级**（`ClientUpdater` 只替换员工端目录，代理 exe 不动），
老电脑上跑的还是旧代理，新加的「补 PATH」代码到不了那里。所以 A 要连带做**代理自升级**：
包里的 `agent\FlyknitAgent.exe` 比正在跑的新时，复制到代理目录旁边，用一个计划任务 / `sc` 重启把自己换掉（失败回滚）。
D 的「运维代理顺带装 WebView2 运行时」也依赖这个。
已经在跑的旧代理没有自升级代码，只能换一次。查代码确认：直接用「安装软件」任务推 `Setup.exe /S` **不行**
（安装程序一停代理，代理就把它连同子进程一起结束了），要给安装程序加 `/deferred`。
**完整方案见 `docs/agent-self-update.md`**（搭桥、自升级、健康检查回滚、总开关、测试）。

**测试**：`PathList` 已有测试；补「已在 PATH 不重复加」「目录里没有 flyknit.exe 不加」「替换失败回滚时不改 PATH」。

**验收**：拿一台命令行功能之前装的电脑，发布新版本 → 自动升级完成 → 新开 cmd 输入 `flyknit --version` 能运行。

## B. 输入框和命令行的斜杠命令

参照 Claude Code（`/compact`、`/permissions`、`/model`、`/context`、`/rewind`……）。
现状：桌面端只有内置的 `/btw`、`/init`，加上 IT 和员工的快捷指令（提示词模板）；命令行有 `/new /resume /plan /usage /clear /help /exit`。
后台大部分能力都有了（见下表「宿主接口」），缺的是斜杠命令这个入口。

### 通用设计

1. **内置命令优先**：和快捷指令重名时以内置为准；后台发布快捷指令时提示「和内置命令重名，不会生效」。
2. **不发给模型**：调权限、换模型这类在本地执行，对话里插一行灰色提示（如「已切换为只读」），不占 token；
   只有 `/compact`、`/review`、`/init` 会调用模型。
3. **不开后门**：每个命令走和按钮完全相同的宿主接口；IT 锁定、部门 / 单台电脑的安全设置、专家封顶、完全权限的二次确认一个不少。
4. **弹出列表分组**：「内置 / 公司 / 我的」；输完命令名按空格显示可选参数（如 `/permission ` 后列出三档）。
5. **三语**：命令名统一英文；说明和提示 `zh-CN` / `vi-VN` / `en-US` 三套（`check-i18n.mjs`）。
6. 手机端不做。

## C. VNext 第 1～4 期

详细设计见 `docs/architecture-vnext.md`（概念定义、存算边界、安全设计、成本控制）。本节只列每期的交付和验收。

### C1. 第 1 期：统一任务模型

**交付**：
- 本机库新增 `tasks`、`runs`、`thread_subscriptions` 表（只加不删）；Task 状态机：待办 / 进行中 / 等确认 / 完成 / 失败 / 停止。
- 统一入口 `TriggerEvent`：员工消息、定时任务（`Scheduling/*`）、事件触发、钉钉 / 企业微信 / 手机（`AgentHost.Channels.cs`）、IT 指令、盯 PR（`AgentHost.PullRequests.cs`）都改为「登记 Task → 开 Run」。
- `TaskGrant`、`RunCheckpoint` / `run_state` 挂到 Task / Run 下；现有行为不变。
- 盯 PR 改成一种 Thread 订阅：已订阅事件直通原对话。
- 任务中心按 Task 展示：来源、授权、进度、预算、停止。

**安全**：非员工本人发起的 Task 一律带 `TaskGrant`；Task 级 token 预算。
**测试**：每种入口都登记成 Task；状态机迁移；订阅直通；停止 / 续跑回归。
**验收**：定时任务、手机发的任务、盯 PR 触发的修复，在任务中心里都能看到来源、授权和进度，能统一停止。

### C3. 第 3 期：Watchdog

**交付**：
- 客户端定时（如每 5 分钟）检查进行中的 Task：最近几步有没有新进展（新文件、计划推进、工具结果变化）。
- 判断「卡住 / 空转 / 跑偏」时提醒员工；连续空转超过阈值自动停下（照常补结果、写审计）。
- 用便宜模型（`title` 场景或新增 `watchdog` 场景），按用途统计里记成 `watchdog`。
- 服务端只看心跳超时（客户端离线时任务中心标出来）。

**测试**：空转判定、提醒、自动停止；不误伤正常的长任务（长时间编译、跑测试）。
**验收**：故意让一个任务反复做同一件事，几分钟内收到提醒并被停下；正常长任务不受影响。

### C2. 第 2 期：Router

**交付**：
- 常驻的轻量 Router 会话（第一期放在客户端 `AgentHost`），便宜模型，**没有执行类工具**，
  只有「归到 Thread / 开 Task / 派 Worker / 回复员工 / 请求确认」这些调度动作。
- 接未订阅的事件（渠道消息、事件触发）：判断归到哪个对话、开新任务还是忽略；先程序过滤（来源、白名单、限流），再模型判断。
- 员工一句话交代多件事时拆成多个 Task 分派；按 Task 汇总进度，多个确认合成一张卡片。
- 新的事件来源默认只观察（预演）。

**安全**：Router 工具清单单测断言没有执行类工具；Worker 权限 ≤ Task 授权；事件内容按数据处理（注入用例）。
**成本**：Router 走便宜模型；按用途统计加 `router`，上线前后对比。
**验收**：同时交代 3 件事，员工只看到一个汇总和合并后的确认卡片；钉钉里的追问自动归到对应任务。

### C4. 第 4 期：并行写（隔离）

**交付**：
- 多个会改文件的 Worker 同时干活时，每个在自己的隔离环境里：本机 Docker 沙箱（沙箱第一期已有，一个 Worker 一个容器）
  或独立 git worktree + 任务分支；产出用 PR 交回，由主对话 / Router 汇总。
- 本机上的写操作仍然一次一个、照常确认；并行写只在沙箱里。
- 只读 Worker 的并行数沿用现有上限（第 0 期不做，保持 3）。

**依赖说明**：`architecture-vnext.md` 里写的依赖是「沙箱第二期」（远程执行节点 + GitHub App）。
如果第二期还没做，先用**本机 Docker 沙箱**实现每个 Worker 一个容器，远程节点以后再接。

**测试**：两个写 Worker 改同一个仓库互不覆盖；出口只推 `flyknit/` 任务分支；容器外的文件不被改。
**验收**：让它「同时修这 3 个 bug」，得到 3 个独立的任务分支 / PR，各自 CI 通过。
