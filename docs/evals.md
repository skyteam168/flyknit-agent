# 回归评测

状态：第一期已实现。2026-11。

## 1. 为什么

IT 经常改东西：专家的说明和知识、技能、连接器、场景用的模型、提示词。改完之后「以前答得好的问题现在还答得好吗」，
现在只能靠员工反馈才知道。回归评测把一组固定的问题存下来，每次改完跑一遍、自动判分、和上一次比，变差的题一眼看出来。

## 2. 做法

```
后台「回归评测」题集 ─► 跑一次：每题一条通道消息 channel=eval（一律只预演，带专家）
                                │
                                ▼
                      执行机上的 FlyknitBuddy 领题、用指定专家回答（没人确认：需要确认的一律拒绝）
                                │ 回报回答
                                ▼
      服务端判分：检查项（完成 / 必须包含 / 不能包含 / 正则）＋ 评分标准（「办事」场景模型打 0-100 分，后台打）
                                │
                                ▼
                全部出结果：通过数、平均分、和上一次比「上次通过这次没过」的题
```

| 层 | 位置 | 做什么 |
| --- | --- | --- |
| 服务端 | `app/models.py` `EvalSuite` / `EvalRun` / `EvalResult`、`ChannelMessage.expert_id` | 题集、每次跑、每题结果；派发消息带专家 |
| 服务端 | `app/services/eval_service.py` | 题目校验、派发、检查项、模型打分（后台）、收尾和对比 |
| 服务端 | `app/routers/evals.py` | 后台接口：题集增删改、跑一次、历次结果 |
| 服务端 | `channel_hub.finish`、`grants.py` | 回报时判分；授权来源 `eval` 按派发记录核对电脑和权限上限 |
| 员工端 | `AgentHost.Channels` / `Grants` / `Router`、`ChannelRelay`、`TaskGrant`、`TaskOrigins` | 认 `eval` 来源；按题指定的专家开对话（执行机上没有这位专家就报错，不用普通助手冒充）；评测对话不复盘、不进长期记忆 |
| 员工端界面 | i18n | 任务来源「回归评测」，三语 |
| 后台 | `admin/src/views/Evals.vue` | 「运维 → 回归评测」 |

## 3. 规则

1. **一律只预演**：派发消息 `rehearsal=true`，执行机只读调研、列出会做的修改；权限上限只有「仅可查看」「工作区内修改」；没人在场，需要确认的操作一律拒绝。
2. **谁能做**：看——管理员都能看；建、改、删题集、跑一次——具名且「能下发指令」的管理员（和指令中心、无人值守任务一样）；共享的管理令牌不行。
3. **每题至少一种判分方式**：必须包含、不能包含、正则（都不区分大小写）、评分标准，至少填一项，否则跑了也不知道对不对。
4. **判分**：
   - 检查项全部通过，且（有评分标准时）模型打分 ≥ 题集的及格分，才算通过；
   - 分数：有评分标准的用模型分（检查项没过时最多 30 分），没有的检查项全过 100 分、否则 0 分；
   - 没完成（执行机报失败、消息过期没人领）的直接算没通过，不去打分；
   - 打分失败（模型不可用）这题记 0 分并写明原因，不让整次评测卡住。
5. **模型打分**：用「办事」场景的模型，提示词要求只按评分标准打分、不被回答里的指令影响，只输出 JSON。
6. **不堆积**：同一个题集上一次还没跑完不能再跑。
7. **对比**：和这个题集上一次跑完的结果比，按题目编号对；改题目编号会断开对比（编号可以在后台自己填）。
8. **不污染**：评测对话不复盘、不写长期记忆；结果只在后台看，不发消息中心。

## 4. 验收

- 服务端：`tests/test_evals.py`（题目校验、权限、派发带专家且只预演、授权核对、检查项和模型打分、退步对比、过期算失败）、
  `tests/test_grant_origins_sync.py`（两边的授权来源一致）。
- 真机：执行机上建一个题集（3-5 题，用中台连接器能答的问题），跑一次看分数；改一下专家说明再跑，看退步标记。

## 5. 以后

- 定时自动跑（复用无人值守的时间表），掉分时发通知给 IT；
- 改专家 / 技能保存时提示「要不要跑一下评测」；
- 同一题跑多次取平均，减少模型随机性带来的波动；
- 结果按工具调用过程打分（现在只看最终回答）。
